# Spec: Assistant Shared Conversation

## Design

默认界面仅呈现幕僚对话与共享输入编辑器。标题和图标工具栏不再附带常驻对话/记忆/执行标签和产品说明。记忆、持续任务与诊断按需打开，返回后保留草稿和阅读位置。图标按钮使用现有 TooltipButton，保留可访问名称、悬停提示和选中状态。

复用主对话 TranscriptPane、TurnCard、DocEditor 和 Composer 的真实渲染/滚动/输入框架。若当前 Composer 的项目控制耦合阻碍使用，只抽出双方实际使用的公共框架或提供类型明确的简化模式，不能填入虚假会话、虚假模型、空操作回调，也不新增幕僚专用气泡/编辑器/滚动实现。共享组件的主会话默认行为不变。

AssistantState 仍是幕僚消息与事项的唯一事实源；渲染适配只是只读投影，不创建 Engine 会话或伪造执行状态。共享 DocEditor 的可选 Markdown 导出调用 BlockNote 自带序列化，递归拒绝不适合纯文本接口的表格、卡片和提及；主 App 的原 DocBlock 接口不变。发送继续使用原 say 接口、稳定 turn_id、失败草稿保留，以及发送期间新草稿保护。记录、处理与执行采用状态不混淆；未明结果仍明确可见，不自动重发。原任务停止/接管、问题、变更、版本绑定验收、记忆内容与范围确认均可达。

处理会话、常规执行记录和跟进目标列表不出现在默认对话。开发者检查可以看原会话与持久控制回执。具体权限问题以及未明结果的原会话核对是必要的恢复入口，不能因隐藏常规执行入口而丢失。减少文字只针对界面导航与操作；保留原问题选项、记忆内容/范围、错误和决定影响。

Ponytail full：局部改样式不能消除重复逻辑；重写整个会话模块会扩大风险。选择在现有模块内提取最小实际共用框架，删除 ChiefThread 被替代的气泡、textarea 和手工滚动路径。Core 与主 App 业务路由不变。

## Acceptance criteria

- [x] AC-1: 主对话与幕僚实际使用同一消息、输入与滚动路径，无第二套气泡/textarea。
- [x] AC-2: 默认只见对话；常规处理/执行会话入口隐藏，图标检查入口可查看记忆及持续任务并返回。
- [x] AC-3: 草稿、稳定重试 id、发送中新增草稿、项目提示及阅读位置保留；不将已记录消息标成执行完成。
- [x] AC-4: 问题、记忆内容与范围确认、版本绑定验收、及时停止/接管、未知结果核对仍可用；图标有可访问名称与提示。
- [x] AC-5: 适用测试、类型、lint、Web/renderer 构建与浅/深色、窄窗实际 React 渲染通过；保留 Core 和无关差异，完成文档检查和资源清理。

## Follow-up 2026-10-06

Ponytail full：这是一处输入框状态呈现问题。复用现有 Pause 和 TooltipButton，把同一真实 enabled 状态变成只读、可键盘聚焦的图标提示。仅改 ChiefThread，不增加控制或第二套状态。AC-2 补充：暂停文案默认不常驻，悬停/聚焦图标仍可读准确提示；enabled 状态不被修改。
